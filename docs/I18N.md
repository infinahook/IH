# Localisation

Le français est la langue par défaut ; l'anglais est pleinement pris en charge.

## Source unique

`locales/fr.json` et `locales/en.json` sont les **seuls** catalogues. Ils sont
consommés par :

- le noyau Rust (`crates/ih-i18n` via `include_str!`) ;
- l'interface React (`src/lib/i18n.ts` via import JSON).

Conséquence : une clé ajoutée d'un côté doit être ajoutée de l'autre, sinon la
compilation des tests échoue.

## Garanties vérifiées par test

- **Parité stricte** FR/EN : `crates/ih-i18n` échoue si une clé manque d'un côté
  (`cles_fr_et_en_identiques`), et `src/lib/i18n.test.ts` vérifie la même
  propriété côté frontend (800 clés).
- **Aucune traduction vide**.
- Repli : locale demandée → français → clé brute.
- Substitution de variables `{name}`.
- Codes de langue normalisés (`fr-FR`, `EN_us`…).

## Règles de contribution

1. Aucun texte visible en dur dans les composants (hors noms de produits).
2. Toujours ajouter la clé dans les **deux** fichiers, au même endroit.
3. Formatage localisé pour les dates et tailles (`src/lib/format.ts`,
   `Intl.DateTimeFormat`).
4. Lancer `cargo test -p ih-i18n` et `npm test` après toute modification.
